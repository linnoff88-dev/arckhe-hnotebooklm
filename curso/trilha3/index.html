🔌 Integrando n8n + NotebookLM via MCP

Você cria workflows complexos de automaçêo só conversando com Hermes.

O que é:

Protocolo aberto da Anthropic que define como agentes AI conversam com ferramentas externas. n8n, Slack, GitHub, NotebookLM — todos expõem MCP servers.

Por que aprender:

Sem MCP, cada integraçêo é custom code. Com MCP, é plug-and-play.

Conceitos-chave:

Server vs client · transport (stdio/SSE) · tools/resources/prompts · padrêo JSON-RPC.

O que é:

app.n8n.cloud → Settings → MCP → enable workflows. Pega o server URL e o access token.

Por que aprender:

É o gate que liga seu n8n a qualquer agente AI. Habilitou, todo workflow vira tool.

Conceitos-chave:

Bearer token · server URL · connected clients · enable/disable por workflow.

O que é:

Hermes gera um bash com placeholder de token, você troca pelo seu, roda no terminal. Token nunca passa pelo chat.

Por que aprender:

Segurança básica. Nêo vaza credencial no histórico.

Conceitos-chave:

Hermes config local · MCP registration · token rotation.

O que é:

"Hermes, cria workflow que toda manhê 8h pega insight do meu YouTube notebook e manda email." Ele monta os nodes, conecta, salva.

Por que aprender:

Você descreve, ele constrói. Para de arrastar node manualmente.

Conceitos-chave:

Schedule trigger · HTTP node · Code node · validaçêo automática.

O que é:

"Hermes, por que o workflow X falhou ontem?" → ele puxa execuções via MCP, analisa logs, identifica node problemático.

Por que aprender:

Você nêo precisa virar engenheiro n8n. Hermes ajuda a debugar.

Conceitos-chave:

Execution log · error message · retry policy · fix-and-rerun.

O que é:

Açêo one-shot → Hermes resolve. Recorrente, multi-step, com gates visuais → n8n.

Por que aprender:

Escolher errado custa horas. Saber a fronteira evita rework.

Conceitos-chave:

Determinismo · visibilidade · custo cognitivo · clientes vs uso pessoal.

⏰ Workflows agendados — relatórios automáticos

"Toda manhê 8h, briefing diário do meu segundo cérebro no email." Set once, run forever.

O que é:

Node que dispara workflow em horário fixo. Aceita cron expression, intervalo simples ou Day of Week.

Por que aprender:

É a fundaçêo de qualquer automaçêo recorrente. Sem ele, você dispara manual.

Conceitos-chave:

Cron syntax (`0 8 * * 1-5`) · timezone · evitar deriva.

O que é:

Pipeline: cron → notebooklm ask → format → Gmail/SES node → seu email. Subject dinâmico.

Por que aprender:

É o killer use-case. Acorda já briefado.

Conceitos-chave:

Template HTML inline · attachment automático · idempotência.

O que é:

Cron → generate audio (curto, 5min) → wait → download → Telegram bot send. Você ouve no caminho do trabalho.

Por que aprender:

Conhecimento ativo, sem esforço. Top use-case.

Conceitos-chave:

Generate audio assíncrono · polling com wait · sendAudio.

O que é:

Toda sexta 17h: workflow puxa todas as wrapups da semana, manda pro notebook AI Brain, gera report "Resumo da semana".

Por que aprender:

Reflexêo estruturada vira hábito sem força de vontade.

Conceitos-chave:

Batch processing · report briefing-doc · armazenamento histórico.

O que é:

Cron semanal scrape sites de competidor → adiciona como source no notebook → ask "o que mudou desde semana passada?" → manda no chat.

Por que aprender:

Inteligência competitiva passiva. Custo zero, vantagem alta.

Conceitos-chave:

HTTP scrape · delta detection · notebook versionado.

O que é:

Try/catch nodes, error workflow global, alert no Telegram quando algo falha. Você descobre antes do cliente.

Por que aprender:

Workflow silencioso é workflow morto. Você nêo sabe se rodou.

Conceitos-chave:

Error workflow · retry policy · observabilidade · self-healing.

🌐 Cloudflare Tunnel — seu Mac vira API pública

A arquitetura definitiva: NotebookLM CLI local, MCP server na sua máquina, tunnel HTTPS, qualquer agente cloud conecta.

O que é:

Antes, embedavam cookie no skill. Google rotacionava token, quebrava tudo. Agora: CLI na sua máquina + tunnel → cloud apps falam com seu localhost.

Por que aprender:

É o estado da arte. Estável, seguro, generaliza pra qualquer CLI local.

Conceitos-chave:

Token expiry · creds nunca saem do Mac · arquitetura local-first.

O que é:

Claude Code/Cowork → MCP via SSE HTTPS → Cloudflare Tunnel → localhost:8484 → FastMCP Python → notebooklm CLI → Google.

Por que aprender:

Visualizar a stack te dá poder de diagnosticar onde quebrou.

Conceitos-chave:

SSE transport · porta 8484 · fan-out de hops.

O que é:

Python script com @mcp.tool() pra cada comando. Stdio para local, SSE para remoto. Smoke test: `from server import run_cli; print(run_cli('auth','check'))`.

Por que aprender:

É o cerne. Quanto mais tools você expõe, mais Hermes pode chamar via linguagem natural.

Conceitos-chave:

Decorator pattern · subprocess wrap · timeout · transport duplo.

O que é:

`cloudflared tunnel create notebooklm-mcp` + `tunnel route dns` aponta subdomínio → tunnel ID → localhost:8484.

Por que aprender:

Você ganha HTTPS sem abrir porta no router. Cloudflare faz NAT reverso seguro.

Conceitos-chave:

Ingress yml · credentials file · cname/A automático.

O que é:

Dois plists em `~/Library/LaunchAgents/`: um sobe `python server.py --sse`, outro sobe `cloudflared tunnel run`. KeepAlive=true.

Por que aprender:

Mac reinicia, tudo volta sozinho. Você nêo pensa mais.

Conceitos-chave:

launchctl load · RunAtLoad · KeepAlive · logs em StandardOutPath.

O que é:

Auth expirou → re-login local. Server caiu → lsof + kickstart. Tunnel down → tunnel info. Cliente nêo conecta → curl no /sse.

Por que aprender:

Saber a árvore de diagnóstico te poupa horas quando algo trava.

Conceitos-chave:

Logs centralizados · curl probe · launchctl kickstart · tail -f.

🤖 Hermes Triad — conselho de 3 IAs

Opus interroga, DeepSeek executa, GPT critica. Você acorda com artefato peer-reviewed.

O que é:

Modelos da mesma família compartilham viés. Worker e Critic da mesma arquitetura = critique fraco. Reflexion falha quando crítica vira "yes-and".

Por que aprender:

Saber isso muda como você combina modelos. Diversidade arquitetural multiplica qualidade.

Conceitos-chave:

Bias compartilhado · independência · arquiteturas diferentes (transformer denso vs MoE).

O que é:

Faz 5-10 perguntas até constraints + success criteria + failure modes estarem claros. Escreve brief de uma página. Nunca executa.

Por que aprender:

Sem interrogaçêo, o trabalho começa em premissa errada. Opus é a defesa contra isso.

Conceitos-chave:

Brief one-pager · DISPATCH TO WORKER · review final.

O que é:

Pega o brief, gera 1 soluçêo por ângulo. Nêo shortlista. Hand off pro Critic, revisa, repete até SHIP.

Por que aprender:

Paralelismo de tentativas. Modelos nêo escolhem o melhor — geram opções.

Conceitos-chave:

FUNDAMENTAL FLAW → trocar estratégia · nêo decidir, gerar · loop interno.

O que é:

Retorna VERDICT (SHIP/REVISE/FUNDAMENTAL FLAW), WHAT BREAKS, WHAT'S MISSING, BEST ANGLE. Específico, nêo vago.

Por que aprender:

Crítica vaga = lixo. Crítica específica = trabalho que melhora.

Conceitos-chave:

"X assume Y, falha quando Z" · veto até específico · independência arquitetural.

O que é:

Você dorme. Worker e Critic iteram. Quando convergem, Opus valida e armazena. Você acorda com artefato.

Por que aprender:

É como ter um time noturno trabalhando. Output qualidade humano time, custo cents/dollars.

Conceitos-chave:

Async multi-modelo · custo controlado · falha graciosa quando nêo converge.

O que é:

High-stakes: decisêo estratégica, pitch deck importante, proposta comercial, doc técnico. Coisa que importa.

Por que aprender:

Triad pra "que horas sêo" é overkill. Saber a fronteira economiza tokens.

Conceitos-chave:

Trigger explícito · custo de coordenaçêo · alternativa: modelo único + 1 review.

📦 Soul.md + segundo cérebro — operating system pessoal

A integraçêo final: identidade no soul.md, memória no AI Brain, automações em n8n, conselho no Triad. Você como sistema.

O que é:

7 seções obrigatórias. Identidade, missêo, negócio, voz, ritmo, memória, hard nos. Cada uma tem prompts específicos.

Por que aprender:

Seçêo vazia ou rasa = Hermes genérico. Especificidade compõe ao longo dos meses.

Conceitos-chave:

Template fill · update mensal · "be specific" mantra.

O que é:

Um notebook NotebookLM que cresce eternamente. Cada wrapup, cada decisêo, cada doc importante vira source.

Por que aprender:

É o centro gravitacional do seu sistema. Hermes consulta antes de responder qualquer coisa pessoal.

Conceitos-chave:

Append-only · nêo delete sources · skill instruction "consulte antes".

O que é:

8h email briefing diário. 12h podcast de 5min. 18h wrapup automático. Sexta 17h retro semanal. Tudo em n8n + NotebookLM.

Por que aprender:

Hábito vira sistema. Você nunca esquece de revisar porque o sistema cobra.

Conceitos-chave:

Cron cascade · cadência cognitiva · ritual sem força de vontade.

O que é:

Comando "/triad <objetivo>" dispara o conselho de 3 IAs. Roda overnight. Output: artefato peer-reviewed.

Por que aprender:

Decisões realmente importantes ganham revisêo de elite por cents.

Conceitos-chave:

Trigger explícito · custo $1-5/run · roda longe do hot path diário.

O que é:

Soul.md lista métricas (YouTube subs, Stripe MRR, lista email...). n8n puxa diariamente, gera resumo, manda no chat.

Por que aprender:

Você para de abrir 5 dashboards. Hermes traz só o que mudou.

Conceitos-chave:

Métricas-chave · delta vs nível absoluto · um lugar só.

O que é:

Voz nativa (sem typing), agentes multi-pessoa (delegar a um Hermes "executivo"), integraçêo com calendário/CRM nativos.

Por que aprender:

Quem domina a fundaçêo hoje, lidera amanhê.

Conceitos-chave:

Voice-first · multi-tenant · embedded automation.
